## 月度计划

### 第 1 个月 · 起步

**Wei Sun**
- [ ] 完成 Godot 4 官方 2D 教程（约 2 周，建立引擎基本认知）
  - 重点：场景/节点系统、Signal 信号机制、物理与碰撞
  - 推荐教程：[Godot 官方「你的第一个 2D 游戏」](https://docs.godotengine.org/en/stable/getting_started/first_2d_game/)
- [ ] 搭建 Godot 项目结构（场景组织、文件夹规范）
- [ ] 建立 Git 协作流程（分支规范：`main` 稳定版，`dev` 开发版，`feat/xxx` 功能分支）
- [ ] 把 HTML 原型的三个核心逻辑跑通：
  1. 可以在格子界面放置/移除武器
  2. 骑士沿格子连接顺序自动巡逻（循环）
  3. 一个敌人从地图边缘走向中心

**TJ**
- [ ] 制作数值平衡表（Excel/Google Sheet）：每件武器 Lv1–3 的理论 DPS，每波次的总敌人血量
- [ ] 收集美术参考图（Pinterest/ArtStation），确定视觉风格方向（像素风 / 手绘风 / 矢量风）
- [ ] 绘制 UI 线框图（低保真草图即可）：格子摆放界面、HUD（城堡血量/金币/波次）、商店界面
- [ ] 整理设计规格文档：把 GDD 中 Wei Sun 最先需要实现的系统（格子、武器、骑士）拆成可执行的开发任务列表

**月末交付：** Godot 里能放格子、骑士会跑、有一个敌人会走——三件事同时出现在屏幕上

### 第 2–3 个月 · 垂直切片

**目标：Act 1 从头玩到尾，有胜负判定，能给陌生人试玩**

这是整个项目最关键的里程碑。能不能做出来、好不好玩，在这里见真章。

**Wei Sun（开发）**
- [ ] 格子系统完整实现
  - 自由拖拽摆放（合法性检查：格子必须相连）
  - 格子上限 9 个
  - 武器放置/移除/升级
- [ ] 骑士巡逻系统
  - 按格子连接顺序循环移动
  - 踩格触发武器（检查 CD）
  - 移速参数可配置
- [ ] 武器触发系统
  - 6 种武器的基础逻辑（近战/远程/AOE/防御/穿透/陷阱）
  - CD 计时、范围检测、伤害结算
  - Lv1–3 升级差异
- [ ] 敌人 AI
  - 寻路：从地图边缘走向界碑（A* 或 NavigationAgent2D）
  - 血量、受击、死亡掉金币
  - 普通兵 + 重甲兵两种类型
- [ ] 波次管理器
  - 按配置文件读取每波敌人数量和类型
  - 波次间隔、商店触发
- [ ] 商店界面
  - 购买 Lv1 武器、升级武器、出售
  - 金币系统
- [ ] 遗物系统骨架
  - 持有列表、效果触发点
  - 实装 4 件遗物（验证系统可用）
- [ ] Act 1 两位 Boss 技能
  - 守关老兵：护盾轮转
  - 铁甲将领：战场号令 + 铁壁强化
- [ ] 胜负判定（城堡 HP 归零 = 失败，Boss 击杀 = 过关）
- [ ] 基础 HUD（城堡血量、金币、当前波次）

**TJ（设计 + 测试）**
- [ ] Act 1 关卡配置文件：每小关波次数量、敌人类型、出兵方向
- [ ] Act 1 商店配置：每关可出现的武器/遗物池
- [ ] 每周和 Wei Sun 对一次进度，测试已实现的功能，记录 Bug 和体验问题
- [ ] 第一轮内测：找 3–5 个朋友玩，记录卡关点和困惑点
- [ ] 根据内测反馈调整数值（这一步会比预期花更多时间）

**月末交付：** Act 1 完整可玩，有粗糙 UI，无占位符系统（所有系统有真实逻辑）

## 分工总览

| | TJ Zhang | Wei Sun |
|---|---|---|
| **核心职责** | 设计主导、产品方向、内测组织 | 引擎主程（Godot + Codex） |
| **持续工作** | GDD 维护、关卡配置、数值平衡 | 系统开发、Bug 修复 |
| **阶段性工作** | UI 线框图、本地化、商店文案 | 技术美术、Steam SDK、打包 |
| **协作方式** | 设计文档→开发规格→实现→测试反馈→调整 | 同上（循环） |

> **关键原则：** TJ 的设计文档直接成为 Codex 的实现规格。文档写得越精确（数值、触发条件、边界情况），开发返工越少。两人每周同步一次进度，保持文档和代码始终对齐。

## 备选方案：抢先体验（Early Access）

如果进度压力大，可以 **Act 1–4 完成后以抢先体验发行**，边卖边做后续内容。

- 发行时间可提前至第 10–12 个月
- 玩家反馈指导 Act 5–8 的设计调整
- 抢先体验售价建议定在正式版的 70–80%
- Hades、杀戮尖塔、Vampire Survivors 都走过这条路
- 前提：Act 1–4 的体验必须足够完整，不能给玩家「半成品」感
