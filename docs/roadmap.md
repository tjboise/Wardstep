---

## 引擎选择

**推荐：Godot 4**

| 对比项 | Godot 4 | Unity |
|--------|---------|-------|
| 费用 | 完全免费，无分成 | 免费起步，$200k+收入后分成 |
| 2D 支持 | 原生优秀 | 够用但偏向3D |
| 学习成本 | GDScript 接近 Python，上手快 | C#，需要有编程基础 |
| Steam 导出 | 官方支持 Windows/Mac/Linux | 同 |
| 社区资源 | Roguelite 案例多 | 更多但信息量大容易迷失 |
| 适合本项目 | ✅ | 可以，但没必要 |

你们已经有 HTML5 Canvas 原型，Godot 的 GDScript 逻辑思路接近，迁移成本较低。**两人里至少一人需要承担引擎主程的角色**——建议先确认 Wei Sun 是否有 Godot 或游戏开发经验，再决定分工。

## 上 Steam 需要什么

| 类别 | 内容 | 备注 |
|------|------|------|
| **开发者账号** | $100 一次性费用（Steamworks） | 需要美国银行账户或 PayPal |
| **游戏本体** | Windows 可执行文件（.exe） | Mac/Linux 可选 |
| **商店素材** | 标题胶囊图、截图（≥5张）、宣传视频 | 美术最晚在上线前2个月完成 |
| **内容分级** | IARC 自评（免费，在线填写） | 约15分钟 |
| **成就系统** | Steamworks SDK 集成 | 可选但强烈建议 |
| **云存档** | Steam Cloud 同步存档 | 可选，体验加分 |
| **语言** | 至少中文 + 英文 | 简体中文是核心用户群 |

## 分阶段计划

### 阶段 0 · 准备（第 1 个月）

**目标：两人对齐，环境搭好，能跑起来**

- [ ] 确认 Wei Sun 的技术方向（会 Godot / Unity / 其他？）
- [ ] 一起过一遍 GDD，对每个系统达成共识
- [ ] 搭建 Godot 项目，建立 Git 协作流程（分支规范、PR 规范）
- [ ] 把 HTML5 原型的核心逻辑（格子布置、骑士巡逻、武器触发）翻译成 Godot 场景
- [ ] 确定美术风格方向（像素 / 手绘 / 矢量），找参考图

**阶段交付：** 能在 Godot 里跑通一个最简单的关卡（无美术，方块代替）

---

### 阶段 1 · 垂直切片（第 2–4 个月）

**目标：Act 1 完整可玩，能让陌生人试玩后说「有趣」**

这是最重要的阶段——验证游戏核心是否有趣，比后续所有内容都重要。

**系统开发（Wei Sun 主导）**
- [ ] 格子拖拽摆放界面（含合法性检查）
- [ ] 骑士巡逻 AI（路径顺序、速度、方向）
- [ ] 武器触发系统（CD、范围检测、伤害结算）
- [ ] 敌人 AI（寻路 → 界碑，血量、受击）
- [ ] 商店界面（购买、升级、出售）
- [ ] 遗物系统骨架（持有、效果触发）
- [ ] Act 1 完整关卡（2 小关 + 精英 + Boss）

**内容与设计（TJ 主导）**
- [ ] 6 件武器的数值调平（Lv1–3）
- [ ] 2 种附魔实装（火焰 + 强化）
- [ ] 4 件遗物实装（验证系统）
- [ ] Act 1 两位 Boss 技能实装（守关老兵 + 铁甲将领）
- [ ] 基础 UI 文案（按钮、提示、数值）
- [ ] 第一轮内测，收集反馈

**阶段交付：** Act 1 可以从头玩到尾，有完整的胜负判定

---

### 阶段 2 · 内容生产（第 5–9 个月）

**目标：8 关全部可玩，全部系统完整**

按关卡分批推进，每两周完成一关：

| 批次 | 内容 | 重点挑战 |
|------|------|---------|
| 批次 A | Act 2–3 | 双侧出兵逻辑，冰面地形效果 |
| 批次 B | Act 4–5 | 地裂重组（格子位移），沙漠巨虫（地下状态） |
| 批次 C | Act 6–7 | 雷击双刃剑机制，潮汐方向反转 |
| 批次 D | Act 8 + 局外成长 | 永恒守护者全技能，挑战诅咒系统，组合记忆 |

**同步进行**
- [ ] 美术资产生产（可以用 AI 辅助出概念图，人工精修关键帧）
- [ ] 音效占位（免费 SFX 库先用着，后期替换）
- [ ] 平衡性电子表格（每件武器/遗物的理论伤害曲线）

**阶段交付：** 8 关全通，功能完整，无占位符

---

### 阶段 3 · 打磨（第 10–12 个月）

**目标：从「能玩」到「好玩」**

这个阶段花的时间往往超出预期——预留足够时间。

- [ ] 手感调整（武器打击感、骑士移动惯性、受击反馈）
- [ ] 视觉特效（命中闪光、灼烧粒子、冻结碎裂）
- [ ] 音乐实装（4 首程序性音轨，按关卡风格切换）
- [ ] 界面动画（卡片翻转、数值跳动、Boss 入场）
- [ ] 大量平衡性测试（找 10 个陌生人玩，记录卡关点）
- [ ] 成就系统（Steamworks）
- [ ] 云存档（Steam Cloud）
- [ ] 中英文本地化校对

**阶段交付：** 内部 Beta 版本，可以给媒体试玩

---

### 阶段 4 · Steam 上线准备（第 13–15 个月）

**目标：商店页面上线，开始积累愿望单**

Steam 商店页面可以在游戏完成前 6 个月上线（只要有基本素材），愿望单积累对首日销量影响极大。

**商店素材制作**
- [ ] 游戏标题 Logo（中英文版本）
- [ ] 胶囊图（460×215、231×87、616×353）
- [ ] 截图 ×8（展示不同关卡/Boss/构筑）
- [ ] 宣传视频（60–90 秒，前5秒抓住人）
- [ ] 商店页文案（简介、详细描述）

**技术收尾**
- [ ] Windows 打包测试（在干净环境安装验证）
- [ ] Steam 内购/DLC 框架（即使首发不用也要留好接口）
- [ ] 崩溃报告系统（Sentry 或 Godot 内置）
- [ ] 新手引导流程

**推广**
- [ ] 在 Reddit（r/roguelikes、r/indiegaming）和 TikTok/B站发开发日志
- [ ] 联系 Steam Curator（游戏策展人）
- [ ] 申请 Steam Next Fest 参展（每年两次，对独立游戏曝光极大）

**阶段交付：** Steam 商店页面上线，愿望单开始积累

## 分工建议

具体分工取决于 Wei Sun 的技术背景，以下是推荐的两种模式：

**模式 A：Wei Sun 是程序员**

| TJ | Wei Sun |
|----|---------|
| 关卡设计、平衡数值 | 引擎主程、系统开发 |
| 所有文案、本地化 | 技术美术（粒子效果、着色器） |
| 用户测试、产品方向 | Steam SDK 集成、打包发布 |
| 概念美术方向（AI辅助出稿） | 游戏内 UI 实现 |

**模式 B：Wei Sun 也偏设计/美术**

这种情况下需要考虑外包程序，或者其中一人在阶段 0 集中学 Godot 3 个月。对于 Roguelite 这类系统复杂的游戏，有一个能独立负责引擎的人是硬需求。

## 最小可行路径

如果资源有限，只做这几件事也能上 Steam：

1. Act 1–4 完整（前4关作为「抢先体验」发行）
2. 4 件武器 + 3 种附魔 + 8 件遗物
3. 2 个职业
4. Windows 版本
5. 中英文

抢先体验（Early Access）是独立游戏常见路径——先发布有限内容，用玩家反馈指导后续开发，同时开始建立社区。Hades、Slay the Spire 都走过这条路。
